Give your agent a budget, not your keys.

noether is a Cardano vault for AI agents. Your team sets each agent's spending limits and allowed payees. The agent pays on its own inside them, and the chain refuses everything else.

Set up a vault Read the code

Three roles, one set of rules

Limits live in the contract, so a compromised agent key or a prompt-injected model can't spend past them.

Owners

A team of keys, for example 2 of 3. They fund the treasury, grant each agent an allowance, approve anything bigger, and can pause every agent in one transaction.

Agent

Pays allowed payees on its own, within a per-payment cap and a budget that resets each period. Its key sits in a separate signer process, never inside the model.

Chain

Checks every payment: the amount, the payee's exact address, the fee, the time window. Payments over the limits need the owners' signatures in the same transaction.

Set up a vault on preprod

About fifteen minutes. You need Node 22+, a free Blockfrost preprod project id, and test ADA from the Cardano faucet.

  1. Get the code

    The Aiken compiler installs itself, pinned and checksum-verified, the first time you build.

    git clone https://github.com/ardey26/noether && cd noether
(cd sdk && npm ci)
scripts/aiken.sh build && scripts/aiken.sh check

  2. Point it at preprod

    export VAULT_NETWORK=Preprod
export BLOCKFROST_PROJECT_ID=preprod...
export VAULT_HOME=.vault

  3. Create keys and fund the first owner

    Send test ADA from the preprod faucet to the address keys show owner_a prints.

    for k in owner_a owner_b owner_c agent; do cli/vault keys gen $k; done
cli/vault keys show owner_a

  4. Create the vault

    Three owners, any two can act. Rotating owners later never changes the vault's address.

    cli/vault vault create --owners owner_a,owner_b,owner_c --threshold 2 \
  --max-validity 10m --payer owner_a
cli/vault treasury fund --ada 150 --payer owner_a

  5. Give your agent an allowance

    25 tADA a day, at most 10 per payment, only to the payees you list. Fees count toward the budget.

    cli/vault allowance grant --agent agent --dest <payee address> \
  --cap lovelace:25:10 --period 1d --expires 30d --fund 60 \
  --from-treasury --propose owner_a --sign owner_a,owner_b

  6. Let the agent pay

    Start the signer that holds the agent's key, then pay with an invoice id. Paying the same id again returns "already paid" instead of a second payment.

    cli/vault signer start --key agent --allowance <unit> --dest <payee address> --socket .vault/signer.sock &
cli/vault agent spend <unit> --to <payee address> --ada 4 --intent-id INV-1001 \
  --purpose "Hosting, October" --signer-socket .vault/signer.sock

Or let your coding agent set it up

The repository ships an agent skill: setup, owner controls, and what to do when a payment is refused. It installs into Codex, Cursor, OpenCode and dozens of other coding agents that support skills.

npx skills add ardey26/noether

The repository is private for now. The command uses your existing GitHub access.

You keep the kill switch

Owner actions need the owner threshold, here two of three.

# stop every agent at once
cli/vault config set --pause --propose owner_b --sign owner_b,owner_c
# take one agent's allowance back into the treasury
cli/vault allowance revoke <unit> --propose owner_b --sign owner_b,owner_c
# approve a payment over the limits: the agent builds it, owners co-sign
cli/vault agent overlimit <unit> --to <address> --ada 30 --intent-id INV-2001 --cosigners owner_a,owner_c --out tx.cbor

What the contract guarantees

  • Hard caps. Per payment and per period, per asset, with the fee included. The period resets on its own.
  • Exact payees. Only addresses on the allowlist, stake part included.
  • Nothing rides along. No minting, no extra tokens, no touching the treasury or another agent's allowance.
  • Owners always win. Pause everything in one transaction, or revoke an allowance even if its data is corrupted.
  • Roles stay separate. Owner signatures never count as the agent's, and an agent key can't also be an owner.
  • An audit trail. Every agent payment commits to an intent record you can read back from the chain.
